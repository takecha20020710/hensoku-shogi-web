# 変則将棋AI Web版

「自分の持ち駒が3枚になったら負け」という変則ルールを、ブラウザでYaneuraOuと対局・検討できるWebアプリです。

## 実装済み

- 9×9盤、駒移動、駒取り、持ち駒、駒打ち、成り・不成
- 二歩、行き所のない駒、打ち歩詰め、王手放置の禁止
- 持ち駒3枚による変則勝敗
- ユーザーの先手・後手選択
- 誰でも利用できる検討モード
- 最善手・次善手・第3候補
- 先手基準の評価値、勝率バー、矢尻付き候補手表示（駒打ちは持ち駒から着手先まで表示）
- KIF・KI2・CSA・USI棋譜のコピー／貼り付け
- 検討開始／停止、1手戻る／進む、棋譜の開始／最終局面へ移動
- 局面変更時に前の探索を中断し、短時間の初回解析を優先
- 対局モードの固定序盤と、プレイヤーが定跡を外れた時点での通常AI思考への切り替え
- 組み込み定跡も確認できる、管理者専用の定跡閲覧・登録・削除画面
- スマートフォン対応
- AI先手／AI後手別の全プレイヤー通算戦績
- 対局モードの確認付き投了と、終局後の検討選択

## 公開方式

`render.yaml`を利用するRender Blueprintです。Dockerのビルド中にYaneuraOu 9.70gitのMaterial版へ持ち駒3枚ルールの探索パッチを適用し、Linux向けにコンパイルします。

秘密の値はコードへ書かず、Renderの画面で設定します。

- `OPENING_ADMIN_PASSWORD`: 定跡閲覧・編集用パスワード
- `OPENING_BOOK_GITHUB_TOKEN`: データ専用ブランチへ定跡を永続保存するFine-grained token
- `SECRET_KEY`: Renderが自動生成
- `VARIANT_PAWN_EVAL`: 攻撃型v2がOFFのとき、`true`で歩だけの実験評価、`false`で従来評価
- `VARIANT_ATTACK_EVAL`: `true`で攻撃型v2、`false`で昨日の歩評価へ即時復帰
- `VARIANT_HOME_ATTACK_EVAL`: `true`で居玉・左右歩攻めv3、`false`で攻撃型v2へ即時復帰

歩の実験評価は、持ち駒3枚の勝敗判定、持ち駒1・2枚の枚数評価、歩以外の駒価値、探索設定を変更しません。序盤の相手玉筋の歩の前進と、二歩により持ち歩を良い筋へ打ちにくい状態だけを評価します。`VARIANT_ATTACK_EVAL`と`VARIANT_PAWN_EVAL`を両方`false`へ変更すれば、従来評価へ戻せます。

攻撃型v2は、玉頭の位取り、相手玉周辺への利き、銀・桂の攻撃参加を強く評価します。攻めが成立しない場合の囲いは小さく評価し、攻撃につながらない12香・92香型の待ち手は減点します。`VARIANT_ATTACK_EVAL`だけを`false`へ変更すれば、昨日の歩評価を変えずに攻撃型v2だけを無効化できます。

居玉・左右歩攻めv3は、序盤の自玉を5九／5一へ残し、4八玉・6八玉／4二玉・6二玉のように一段上がって歩攻めの目標になる手を抑えます。相手玉が居玉なら4筋・6筋の歩の前進をどちらも強く評価し、端角の押し売りを止める6四歩（先後反転時は4六歩）を残せる相手飛車側の歩攻めを少しだけ優先します。`VARIANT_HOME_ATTACK_EVAL`だけを`false`にすれば攻撃型v2へ戻せます。

歩探索v2は、特定の盤面や座標に限定せず、先後両方の歩打ち・歩突き・歩取り・歩捨て・成り／不成を探索木の全階層で少し早く調べます。歩の手に対するfutility、SEE、履歴枝刈りとLMRを段階的に緩め、親局面と1手進めた局面で同じ探索規則が働くようにしています。評価値そのものへ歩手ボーナスは加えません。

歩探索v3はv2を維持したうえで、着手後の歩が直ちに相手駒へ当たる「強制力の高い歩」を追加判定します。歩打ち・歩突き・成り／不成の別、筋、段、先後を固定せず、相手の飛車・角など価値の高い駒へ当たるほど候補順を上げます。この手は履歴・futility・SEEによる早期枝刈りから除外し、LMRをさらに緩和します。またルート局面では通常候補より3手深い個別検証を行い、通常探索では候補外なのに、その手を指した直後だけ評価値が反転する現象を抑えます。これは評価関数への加点ではなく、読む順番・枝刈り・探索深さの変更です。

探索v4では歩だけでなく、飛車・角・金銀桂香・成駒を含む全駒種について、着手後の駒が相手に取られ得て通常将棋のSEE（静的交換評価）では駒損と判定される「押し売り候補」を共通検出します。該当手は通常将棋向けのcapture futility、SEE、履歴、quiet futilityによる早期枝刈りから除外し、LMRも1.5手分緩和します。これにより、3枚ルールでは勝敗に直結し得る55飛・52歩成のような手を、通常将棋の駒損だけを理由に浅く読んだり候補から消したりしにくくします。駒得評価は維持し、評価値への固定ボーナスは加えていません。したがって「押し売りなら常に好手」と決め打ちせず、候補を十分な深さまで読んだ結果で比較します。

探索v5では、v4の「着手直後に相手から取られる押し売り」だけでなく、駒取り・成りから数手後に押し売りへつながる連鎖の入口も対象にします。ルート局面の駒取り、成り、強制力の高い歩、直接の押し売り候補を通常手より3手深く個別確認します。これにより、55飛のように着手直後のSEEだけでは特殊性を検出できない手も、数手後の持ち駒3枚ルールまで読んで比較します。全合法手への固定加点や全手一律延長は行わず、戦術的な入口だけを対象にして探索速度との両立を図ります。

画面から登録した定跡は`opening-book-data`ブランチの`opening_book.json`へ保存します。トークンは対象リポジトリのContentsを読み書きできる最小権限に限定してください。保存後は再デプロイを待たず、現在稼働中の対局へ即時反映されます。

AI戦績も同じデータ専用ブランチの`game_stats.json`へ保存します。集計開始後の対局だけを対象とし、AI先手／AI後手ごとに勝敗を記録します。署名済み対局トークンと対局IDで、同一対局の二重加算を抑止しています。

## ShogiGUI用Windowsエンジン

GitHub Actionsの「Build Windows engine」から、`HensokuShogi-Material-Windows-x64`を取得できます。AVX2版と互換用SSE4.2版を収録し、Web版と同じ変則探索および居玉・攻撃重視v3までの評価を既定で有効にしています。公式YaneuraOuの既存exeはWeb側から変更できないため、ShogiGUIには生成されたexeを別エンジンとして登録します。

## ローカル確認（開発者向け）

Dockerが使える環境では、イメージをビルドしてポート10000で起動できます。`OPENING_ADMIN_PASSWORD`と`SECRET_KEY`は起動時の環境変数として渡してください。
